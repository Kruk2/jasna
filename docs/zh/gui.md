# 使用 GUI

每个设置都有提示。把鼠标移到旁边的 ⓘ 图标上即可查看。

安装或更新后的首次启动需要更长时间。主窗口打开前，启动窗口会显示安装检查进度。
如果检查失败，错误会留在屏幕上。

请把 Jasna 安装在本地磁盘上（Windows 用 NTFS；Linux 用 ext4、Btrfs、XFS 或 ZFS），
并放在路径中没有中文、日文、带重音的字母或其他非英文字符的文件夹中。不支持网络磁盘。
请使用固态硬盘（SSD）：在机械硬盘（HDD）上 Jasna 启动和加载模型都很慢，启动时会给出警告。

## 队列

- 用**添加文件**添加视频或图片，或用旁边的文件夹图标添加整个文件夹。
  也可以直接把文件拖放到队列上。
- 拖动队列项的把手可以调整顺序。Jasna 按从上到下的顺序处理队列。
- 超过 20 个项目时，用队列下方的箭头翻页。所有页面都会按顺序处理。
  拖动只能在同一页内进行。
- 每个视频上的按钮：
  - **剪刀**打开[区间编辑器](segments.md)。
  - **播放**在视频播放器中打开视频，并保持暂停。
  - **三点**（或右键点击）：**打开所在文件夹**、**复制路径**、
    **打开修复后的输出**，以及**重新加入队列**（把已完成、失败或跳过的项目放回队列末尾）。
  - **叉号**移除该项目。
- 处理时，每个项目都会显示进度、FPS 和剩余时间。
- **▶**（开始）会从暂停队列中待处理的项目继续，已完成的项目不会重做。
  队列完成后再按 ▶，会使用当前设置重新处理所有项目。
- 使用 LTX 的任务显示 **Ⅱ**（暂停）。确认后会保留已保存的进度，并将当前项设为**待处理**。
  点击 **▶** 可继续。如果输入、设置或 Jasna 版本改变，替换已保存的进度前会先询问；
  选择**否**会保留进度并跳过该视频。
- 其他任务使用 **■**（停止），下次会重新开始；未完成的输出按**文件冲突**设置处理。
- 处理中关闭窗口时会先询问：**最小化**继续处理，**停止并退出**结束处理。
- **清除已完成**移除已完成的项目。**清空**移除全部项目。

## 输出设置

- **与输入相同**会把每个结果保存在原文件旁边。
- 输入文件夹路径，或用文件夹按钮选择其他保存位置。这会关闭**与输入相同**。
  点击**与输入相同**可重新打开它。
- **输出文件名模板**设置输出文件名。`{original}` 是输入文件名。如果某个文件名
  会覆盖其他文件，相关队列项会立即被标出。
- **文件冲突**（位于**基本处理**）决定输出文件已存在时怎么办：**自动重命名**（默认）、
  **覆盖**或**跳过**。

## 预设

设置上方的工具条可以把全部设置保存为一个名称。为每类视频建一个预设，例如
“1080p 快速”和“4K 最佳质量”，一键切换。Jasna 重启后会记住上次使用的预设。

## 每个视频的单独设置

在[区间编辑器](segments.md)中设置的检测模型和检测阈值只保存给这一个视频。
队列中的其他视频保留各自的设置。

## 视频播放器

点击页眉中的**视频播放器**，可以边修复边观看视频。不会生成输出文件。

1. 选择检测模型、检测阈值，需要的话再选二次修复（**RTX Super Res** 或 **UNet 4x**）。
2. 点击**选择视频**。
3. 按播放。

- **空格**：播放或暂停。**左/右方向键**：跳转 30 秒。
- 全屏时，把鼠标移到底部边缘即可显示控制栏。
- 更改模型、检测阈值或二次修复后，会从当前位置重新开始播放。
- 状态会显示已提前修复好的秒数。如果它反复降到零，说明在这些设置下
  你的 GPU 太慢，无法实时播放。音频会等待更多画面准备好。
- 播放器总是使用 BasicVSR++，不使用 LTX。
- 只有在队列和**修复预览**都没有运行时才能使用。

## 逐张处理图片

对于静态图片，**交互式处理图片**（位于**图像修复（静态图片）**部分）会打开一个
左右对比视图。逐张浏览图片，尝试其他种子，对比原图、遮罩和结果，只保存你喜欢的
结果。这比每次尝试都重跑整个任务快得多。

## 系统检查

每个版本首次启动时，Jasna 会检查 FFprobe、GPU、驱动和安装路径。你可以从页眉
再次运行它，例如在更新驱动后。

在 AMD 上，它还会检查 AMD 驱动和 AMD 的 AMF 视频运行库（Jasna 读写视频需要它）。
如果驱动比测试过的版本旧，或无法读取版本，会显示警告，但仍可继续。如果之后视频处理失败，
请按[快速开始](../../README.zh.md#快速开始)安装驱动和 AMF。

## 其他设置

- **语言**：首次启动时使用系统语言。可在页眉中更改。重启 Jasna 后所有文字
  才会全部切换。
- **日志**：底部工具条的日志按钮显示实时日志。**导出**会保存最后 5000 行。
  反馈问题时请附上它。
- **系统状态**：处理时底部工具条会显示 GPU、显存、内存和 CPU 占用。

## 激活支持者模型

支持者模型（UNet 4x、SD 1.5、LTX）需要激活。在页眉中打开**激活 Jasna**。

输入你的**许可证码**，点击**激活**。Jasna 会自动选择核验许可证的方式：

- **有 TPM 2.0 安全芯片的电脑**（大多数 Windows 11 电脑）：之后可离线使用。在 Windows 上
  可能会弹出一次权限请求，这是为离线使用进行的一次性许可证检查。如果拒绝，Jasna 会改为在线核验；再次输入许可证码即可切换为离线。
- **其他电脑、租用的 GPU 和 Docker**：Jasna 使用支持者模型时会在线核验许可证，请保持电脑联网。
  如果一直断网，队列会停止。恢复联网后重新开始即可。

需要了解：

- 页眉会显示**已激活（离线）**或**已激活（在线）**。
- 一个许可证码可**同时在 3 台设备上**使用。同一台电脑再次激活不会占用新名额。
- 重新打开**激活 Jasna**可查看**使用中的设备**：离线电脑加上此刻在线使用支持者模型的设备。
  查询需要联网。
- 离线电脑会一直占用名额。重装系统或更换显卡、硬盘、内存不会改变；更换主板或在 BIOS 中
  重置安全芯片算新电脑。要释放名额，请联系你获得许可证码的地方。
- 在线设备只有 Jasna 运行时才占用名额。提示“已在 3 台设备上使用”？请先关闭其他设备上的
  Jasna，再重新开始。
- 有安全芯片的电脑仍在线使用时，激活提示会说明原因。
- 有安全芯片的 Linux：Jasna 会提示运行 `sudo usermod -aG tss $USER`。重新登录后再激活一次，
  即可离线使用。NixOS 需先在 `configuration.nix` 中加入 `security.tpm2.enable = true;`，并把用户加入 `tss` 组。
- 在 distrobox 或 toolbox 里使用 Linux：容器必须能使用主机的 TPM 组。在容器内运行
  `ls -ln /dev/tpmrm0` 可看到组号；如果 `id` 里没有这个组号，请加上
  `--additional-flags "--group-add <组号>"` 重新创建容器，然后再激活一次。
- AMD 电脑提示"没有厂商证书"：请更新 BIOS。较旧的 AMD 安全芯片固件常常没有证书。
  如果仍不行，Jasna 会在线使用。
- 从旧版 Jasna 升级？第一次处理时激活会自动沿用。如果提示激活已转移，请重新输入许可证码。
  同一台电脑上的 Jasna 0.11 仍可继续使用。
- 有 Jasna 0.10 的邮箱和密钥？旧密钥已不能使用，请向购买的地方申请新的许可证码。

许可证码只能从 [Buy Me a Coffee](https://buymeacoffee.com/kruk2)、
[Unifans](https://app.unifans.io/c/kruk2)，以及面向中国的
[闲鱼 (Xianyu)](../../README.zh.md#在闲鱼购买) 获得。支持档位：见
[支持本项目](../../README.zh.md#支持本项目)。
界面顶部的 **闲鱼** 按钮会显示卖家的闲鱼二维码，用闲鱼 App 扫描即可打开卖家主页购买。
