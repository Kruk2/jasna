# VRAM と GPU 使用量の調整

VRAM が少なくなると、Jasna は待機中のフレームをシステム RAM へ移し、また
戻します。そのための設定は不要です。以下の設定で、処理が使う VRAM と GPU
時間を変えられます。

クリップとコンパイルの設定は BasicVSR++ 用です。LTX はメモリを自分で管理します。
[LTX に必要なもの](models.md#ltx-に必要なもの)を参照してください。

## 最大クリップサイズと時間オーバーラップ

Jasna はモザイクをクリップ単位で復元します。クリップとは、まとめて処理される
フレームのまとまりです。

- **最大クリップサイズ**（**エキスパート**タブ）: クリップの最大の長さ（フレーム数）です。長いほど
  結果が安定しますが、VRAM を多く使います。
- **時間オーバーラップ**: 2 つのクリップのつなぎ目を滑らかにします。大きい
  ほど時間がかかります。`20` を超えても通常は効果がありません。

おすすめの設定:

- VRAM に収まる範囲で最も大きい**最大クリップサイズ**を使います。クリップが
  大きいほど安定し、*しかも*速くなります。
- **時間オーバーラップ**を `8` から `20` の間にします。

1080p 動画 1 本、オーバーラップ 8、RTX 5090 での結果です。時間は環境で
変わりますが、傾向は同じです:

| 最大クリップサイズ | 時間 | VRAM |
| -------------:| ----:| ----:|
| 30            | 51 秒 | 3.4 GB |
| 60            | 40 秒 | 3.7 GB |
| 90            | 34 秒 | 4.1 GB |
| 180           | 35 秒 | 5.0 GB |
| 360           | 32 秒 | 6.3 GB |
| 720           | 33 秒 | 8.0 GB |

小さいクリップは速くなるのではなく、**遅く**なります。オーバーラップの
フレームはクリップごとに処理し直すため、クリップが増えるほど同じ作業が
増えます。`180` くらいから時間は良くならず、VRAM だけが増えます。4K 動画は
同じクリップサイズで約 1.5 倍の VRAM を使います。

```bash
jasna --input input.mp4 --output output.mkv --max-clip-size 90 --temporal-overlap 8
```

## VRAM が足りない？

1. **最大クリップサイズ**を下げます。各段階でどれだけ使うかは上の表を参照
   してください。
2. 二次復元をオフにするか、より軽いものを使います
   （[比較](models.md#速度と-vram-の比較)を参照）。
3. GPU を使う他のアプリ（ブラウザー、ゲーム、動画プレーヤー）を閉じます。

VRAM が 4～6 GB のカード: 1080p 動画では最大クリップサイズ `30` から
始めてください。4K ではさらに必要です。

**BasicVSR++ コンパイル**をオフにしても効果はありません。節約できるのは 0.5 GB
未満で、処理は約 3 倍遅くなります。

## モデルのコンパイル

NVIDIA では、Jasna は検出モデルと復元モデル（使う場合は UNet 4x も）を
お使いの GPU 専用にコンパイルします（TensorRT）。これで処理がずっと速くなります。AMD ではコンパイルしません。

- 最初のジョブで行われ、約 **15～60 分**かかります。この間は他のアプリを閉じ、
  PC を使わないでください。
- 結果は `model_weights` に保存され、以後のジョブでも使われます。
- 古い Jasna から新しい Jasna へ `model_weights` をコピーすれば、もう一度
  待つ必要はありません。

復元モデルのコンパイルはオフにもできますが、その理由はほとんどありません。

```bash
jasna --input input.mp4 --output output.mkv --no-compile-basicvsrpp
```

同じ 1080p 動画、クリップサイズ 180:

|                          | 時間 | VRAM |
| ------------------------ | ----:| ----:|
| コンパイルあり（デフォルト） | 33 秒 | 5.0 GB |
| コンパイルなし            | 107 秒 | 4.6 GB |

最大クリップサイズを変えても、コンパイルはやり直しになりません。

## 上級者向けの環境変数

トラブルシューティングやテスト用です。ほとんどの人はデフォルトのままが最適です。

| 変数 | 値 | 内容 |
| --- | --- | --- |
| `JASNA_LTX_VAE_ENCODER` | `full`、`half`、`max` | LTX の動画エンコーダーを選びます。`half` と `max` は速く、少しやわらかい仕上がりです。デフォルト: 基本画質・標準画質は `half`、それ以外は `full`。 |
| `JASNA_LTX_VAE_DECODER` | `full`、`half`、`max` | LTX の動画デコーダーを選びます。`half` と `max` は速く、少しやわらかい仕上がりです。デフォルト: 基本画質・標準画質は `max`、それ以外は `full`。 |
| `JASNA_DECODE_BACKEND` | `auto`（デフォルト）、`vali`、`pyav-hw`、`pyav-sw` | 入力動画の読み込み方法を選びます。動画が開けない、またはフレームが壊れる場合は `pyav-sw`（低速）を試してください。`vali` は NVIDIA のみです。 |
| `JASNA_TRT_CUDAGRAPHS` | `1`（デフォルト）、`0` | NVIDIA: `0` でコンパイル済み BasicVSR++ の高速化をオフにします。GPU エラーが出る場合に試してください。 |
| `JASNA_AMD_GRAPHS` | `1`（デフォルト）、`0` | AMD: `0` で BasicVSR++ の高速化をオフにします。GPU エラーが出る場合や VRAM が足りない場合に試してください。 |
| `TORCH_ROCM_AOTRITON_ENABLE_EXPERIMENTAL` | `1`（デフォルト）、`0` | AMD: `0` で高速なアテンションモードをオフにします。GPU エラーが出る場合は `JASNA_AMD_GRAPHS=0` と一緒に試してください。 |
| `TVAI_MODEL_DATA_DIR`、`TVAI_MODEL_DIR` | フォルダーのパス | Topaz Video のモデルフォルダー。TVAI に必要です（[二次復元](models.md#二次復元)を参照）。 |

Windows: Jasna フォルダーでコマンドプロンプトを開き、変数を設定して同じウィンドウで
Jasna を起動します（2 行を `.bat` ファイルとしてそこに保存しても構いません）。

```bat
set JASNA_LTX_VAE_DECODER=full
jasna.exe
```

Linux（AMD では `./jasna` の代わりに `./run_jasna_amd.sh` を起動）:

```bash
JASNA_LTX_VAE_DECODER=full ./jasna
```

この設定は、そのウィンドウを閉じるまで有効です。
