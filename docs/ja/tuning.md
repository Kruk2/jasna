# VRAM と GPU 使用量の調整

Jasna は VRAM を自動管理します。VRAM が不足すると、キュー内のフレームを
一時的にシステム RAM へ移し、また戻します。そのための設定は不要です。
以下の設定は、処理が使う VRAM と GPU 時間の量を調整するものです。

## 最大クリップサイズと時間オーバーラップ

Jasna はモザイクをクリップ — まとめて処理されるフレームの連続 — 単位で
復元します。**最大クリップサイズ**はクリップの最大長を決めます
（長いほど時間的な一貫性が向上し、VRAM を多く使います）。
**時間オーバーラップ**はクリップのつなぎ目を滑らかにします。オーバー
ラップが大きいほど処理時間が増えます。`20` を超えても通常は大きな効果は
ありません。

推奨の開始点:

- GPU のメモリが許す範囲で最も大きい**最大クリップサイズ**を使います。
  クリップが大きいほど安定し、しかも速くなります。
- **時間オーバーラップ**を `8` から `20` の間に設定します。
- クロスフェードは有効のままにします（処理済みのフレームを再利用する
  ため、追加コストはありません）。

1080p 動画 1 本、オーバーラップ 8、RTX 5090 での実測値です。時間は環境で
変わりますが、傾向は同じです:

| 最大クリップサイズ | 時間 | VRAM |
| -------------:| ----:| ----:|
| 30            | 51 秒 | 3.4 GB |
| 60            | 40 秒 | 3.7 GB |
| 90            | 34 秒 | 4.1 GB |
| 180           | 35 秒 | 5.0 GB |
| 360           | 32 秒 | 6.3 GB |
| 720           | 33 秒 | 8.0 GB |

小さいクリップは速くなるどころか**遅く**なります。オーバーラップ部分の
フレームはクリップごとに処理し直すため、クリップが増えるほど無駄が増えます。
`180` あたりから時間は改善しなくなり、VRAM だけが増えます。4K 動画は同じ
クリップサイズで 1.5 倍ほどの VRAM を使います。

```bash
jasna --input input.mp4 --output output.mkv --max-clip-size 90 --temporal-overlap 8 --enable-crossfade
```

## VRAM が足りない？

1. **最大クリップサイズ**を下げます — 各段階のコストは上の表を参照してください。
2. セカンダリ復元をやめるか、より軽いものを選びます
   （[比較表](models.md)を参照）。

モデルコンパイルの無効化は、もはや VRAM 節約の手段としては有効ではありません。
0.5 GB 未満しか空かず、処理は約 3 倍遅くなります。

## 復元モデルのコンパイル

NVIDIA では、復元モデルは TensorRT エンジンにコンパイルされます。無効化も
できますが、そうする理由はほとんどありません（AMD は常に PyTorch モデルを
使います）:

```bash
jasna --input input.mp4 --output output.mkv --no-compile-basicvsrpp
```

同じ 1080p 動画、クリップサイズ 180 での実測値:

|                          | 時間 | VRAM |
| ------------------------ | ----:| ----:|
| コンパイルあり（既定）    | 33 秒 | 5.0 GB |
| コンパイルなし            | 107 秒 | 4.6 GB |

エンジンは最大クリップサイズに関係なく同じものを使うため、この設定を変えて
も再コンパイルは起きません。
