# UNet 4x on ROCm 10.1

RX 9060 XT (`gfx1200`), Linux, Python 3.12, Torch 2.14.0+rocm10.1.0,
HIP 7.16.26385, Triton 3.8.0+git669b31ac.rocm10.1.0. FP16, batch one,
256×256 input and 1024×1024 output.

| Network forward | Median ms/patch | Patches/s |
| --- | ---: | ---: |
| Eager PyTorch | 11.586 | 86.3 |
| Compiled PyTorch, preserved FP16 rounding | 6.848 | 146.0 |

Compilation is **1.69× faster** in this test. These are network timings,
including the high-resolution feedback copy, rather than end-to-end video
throughput. Detection, BasicVSR++, blending and encoding are excluded. Timing
uses GPU events, five warm-up calls and the median of three sets of 20 calls,
with an exclusive GPU lock and six CPU threads. Raw results are in
[the CSV](2026-10-27_unet4x_rocm101.csv).

The selected compile settings are `fullgraph=True`, `dynamic=False` and
`options={"emulate_precision_casts": True}`. Default fusion without preserved
rounding diverged over recurrent calls. The `max-autotune` trial was stopped
after minutes of convolution tuning; it has no complete timing result and is
not the default. The first compiled accuracy run took 58.8 seconds; the final
run with existing compiler caches took 6.17 seconds. These startup figures
include six accuracy calls and reference loading.

Accuracy was checked against the existing TensorRT engine on an RTX 5090:
five deterministic synthetic frames (seed 83), including the bootstrap call,
gave about 55–56 dB PSNR. This measures agreement between backends, not image
quality against ground truth. A separate 90-frame test through the shared
restorer compared eager and compiled AMD output: worst frame mean absolute
error was 0.213 on the 0–255 scale; the largest individual channel difference
was 74. Results are not bit-exact. Overlap selection, cleanup and FP32
inference also passed on the RX 9060 XT.

Windows CPU validation used Torch 2.14.0+rocm10.1.0 and
triton-windows 3.8.0.post29: the HIP helper compiled with NX, ASLR and
high-entropy VA; an AMD `gfx1200` kernel compiled offline; compiler-cache tests
passed. The VM has no AMD GPU, so Windows inference remains untested.
