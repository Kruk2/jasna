# Windows: v0.12.2 vs the rebuilt v0.12.3 release (2026-11-09)

Same setup as `2026-11-09_v0.12.2_vs_v0.12.3_windows.md`, measured again on the 0.12.3 release built from main
`2065852e` (which replaced the earlier `307f8083` build): RTX 5090 (driver 610.74), Windows 11, both builds on the
local SSD, v0.12.2 from the official archive (tag `v0.12.2`, `12510264`). One 15 s 1080p30 clip (449 frames), CLI
defaults plus the canonical benchmark settings (`scripts/benchmark_releases.py`: clip size 180, overlap 15, no
secondary restoration), HEVC output. Wall time is the whole job, measured outside the program; job times are medians
of three runs alternating the two builds after one discarded first run per build and mode. Per-run values in the
`.csv`.

| Run | v0.12.2 | v0.12.3 |
|---|---|---|
| BasicVSR++ | 20.7 s | 21.7 s (+1.1 s, +5 %) |
| LTX Standard (2 steps) | 102.3 s | 105.0 s (+2.7 s, +3 %) |

| Phase (BasicVSR++, median of 3) | v0.12.2 | v0.12.3 |
|---|---|---|
| Start until "installation verified" | 6.7 s | 7.0 s |
| Then until the first log line (app start, detector load) | 6.5 s | 7.6 s |
| Then until exit (the actual restoration) | 7.2 s | 7.4 s |

v0.12.3 starts about 1.4 s slower; the restoration itself runs at nearly the same speed. The LTX per-window rates are
unchanged (encode 0.47-0.48 s per window, denoise 0.48 s per window-step, decode 0.77 s per window at 512); in a timed
pair the LTX pass took 82.5 s (v0.12.2) and 86.0 s (v0.12.3), most of it in the encode pass (42.4 vs 45.6 s), which
includes starting the LTX worker. The difference is per job, not per frame.

- The v0.12.3 LTX output matches v0.12.2: PSNR 54.1 dB between the two outputs (minimum 50.1 dB per frame), against
  43.5 dB between the input and the v0.12.2 output.
- First runs: BasicVSR++ 215.8 s / 179.9 s (TensorRT detector engine), LTX 477.8 s / 502.5 s (GPU kernels and the
  LTX speed test).

Not measured: longer videos, Fast mode (NVFP4), other GPUs, AMD.
